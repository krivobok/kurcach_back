# Серверная часть веб-приложения «Крестики-нолики»

Курсовой проект по теме: серверная часть веб-приложения «Крестики-нолики».

Технологии: Python, Flask, Jinja2, SQLite, REST API, WebSockets, PyCharm, Git, GitHub. Архитектура оформлена в стиле MVC: модели, репозитории, сервисы, контроллеры и представления разделены по каталогам.

Нормативная база: инструкция по организации и проведению курсового проектирования СМКО МИРЭА 7.5.1/04.И.05-18.

## Быстрый старт

1. Установить зависимости:

```powershell
python -m pip install -r requirements.txt
```

2. Запустить сервер:

```powershell
python run.py
```

3. Открыть сайт:

```text
http://127.0.0.1:5000
```

## Что реализовано

- Регистрация и вход пользователей.
- Два типа аккаунтов: клиент и администратор.
- Защита API через Bearer Token.
- Игровые комнаты: публичные, закрытые, AI-комнаты и матчмейкинг.
- Игра с компьютером без ручных API-запросов.
- Игра двух пользователей через комнаты.
- Упрощённый HTML-интерфейс: вход, регистрация, создание комнат и ходы выполняются обычными кнопками и формами.
- Кликабельное игровое поле в браузере без необходимости отправлять запросы вручную.
- Подсказка лучшего хода.
- Серверный анализ позиции: лучший ход, немедленные угрозы, потенциал линий, процент заполнения поля и текстовая рекомендация.
- Сдача партии и реванш.
- Чат комнаты.
- Replay партии: история всех ходов и состояний поля.
- Рейтинг игроков, статистика, каталог достижений и история партий пользователя.
- Админ-панель для управления пользователями и комнатами.
- Журнал действий администратора и пользователей.
- REST API и WebSocket-события.
- Swagger/OpenAPI и Postman-коллекция.
- Тесты Pytest для правил игры, API, сервисов, страниц, ролей и админских сценариев.

## Аккаунты и роли

При регистрации можно выбрать тип аккаунта:

- `Клиент` - обычный игрок.
- `Администратор` - пользователь с правами управления сайтом.

Клиент может:

- играть с компьютером;
- создавать комнату для другого игрока;
- присоединяться к комнатам;
- делать ходы;
- пользоваться подсказкой;
- сдаваться и начинать реванш;
- смотреть рейтинг;
- писать в чат своей комнаты.
- смотреть серверную рекомендацию по позиции прямо в комнате;
- получать историю своих партий через API.

Администратор может:

- открывать `/admin`;
- смотреть сводку проекта;
- смотреть список пользователей;
- выдавать и забирать роль администратора;
- блокировать и разблокировать пользователей;
- отзывать активные токены пользователей;
- удалять пользователей;
- смотреть список комнат;
- завершать, закрывать и удалять комнаты;
- смотреть журнал действий.

Код администратора по умолчанию:

```text
admin123
```

Перед запуском его можно заменить:

```powershell
$env:ADMIN_REGISTRATION_CODE="my-secret-code"
python run.py
```

## Статусы комнат

Комната может иметь следующие статусы:

- `waiting` - ожидает игроков.
- `playing` - идёт игра.
- `finished` - партия завершена, игроки могут начать реванш.
- `closed` - комната закрыта администратором, новые входы, ходы и реванши запрещены.

В админ-панели есть три действия:

- `Завершить` - переводит комнату в `finished`; если игра была активна, она завершается.
- `Закрыть` - переводит комнату в `closed`; играть, входить и начинать реванш больше нельзя.
- `Удалить комнату` - физически удаляет комнату, связанную игру, ходы и чат. Старые ссылки возвращают `404`.

## База данных

Используется SQLite. По умолчанию файл создаётся автоматически:

```text
instance/tictactoe.sqlite3
```

Основные таблицы:

- `users` - пользователи, роли, рейтинг, статус.
- `auth_tokens` - токены авторизации.
- `rooms` - игровые комнаты.
- `room_players` - игроки в комнатах.
- `games` - партии.
- `moves` - ходы.
- `chat_messages` - чат комнаты.
- `matchmaking_queue` - очередь подбора соперника.
- `user_stats` - статистика пользователей.
- `achievements` и `user_achievements` - достижения.
- `game_events` - события партии.
- `audit_log` - журнал действий.

## REST API

API начинается с префикса `/api`.

Основные группы:

- `Auth`: регистрация, вход, выход, текущий пользователь.
- `Users`: список пользователей, профиль, статистика, история партий.
- `Rooms`: комнаты, вход, готовность, реванш.
- `Games`: ходы, AI-ход, подсказка, анализ позиции, сдача, replay.
- `Chat`: история и отправка сообщений.
- `Matchmaking`: очередь подбора соперника.
- `Stats`: рейтинг, каталог достижений и общая статистика.
- `Admin`: управление пользователями, комнатами и журналом.

Полная спецификация доступна в Swagger:

```text
http://127.0.0.1:5000/swagger
```

## Postman

Импортировать collection можно по URL:

```text
http://127.0.0.1:5000/api/postman.json
```

Импортировать environment:

```text
http://127.0.0.1:5000/api/postman-environment.json
```

Рекомендуемый порядок проверки:

1. `Auth / Register client` или `Auth / Login`.
2. `Rooms / Create AI room`.
3. `Games / Make move 0,0`.
4. `Games / Game detail`.
5. `Games / Game analysis`.
6. `Games / Replay`.
7. Для админки: `Auth / Register admin`, затем папка `Admin`.

Коллекция автоматически сохраняет переменные `token`, `user_id`, `room_id` и `game_id`.

## WebSockets

Используется Flask-SocketIO. Основные события:

- `user.join` - авторизация socket-сессии.
- `room.subscribe` - подписка на комнату.
- `room.join` - вход в комнату.
- `room.ready` - готовность игрока.
- `game.move` - ход игрока.
- `chat.send` - сообщение в чат.
- `matchmaking.queue` - очередь подбора.
- `room.updated` - обновление комнаты.
- `game.move_made` - ход принят.
- `game.finished` - партия завершена.
- `chat.message` - новое сообщение.

Подробно события описаны в `x-websocket-events` файла [docs/openapi.json](docs/openapi.json).

## Частые проблемы

Если пользователь не может войти:

- проверьте логин и пароль;
- убедитесь, что аккаунт не заблокирован администратором;
- если токен старый, выполните вход заново.

Если нельзя войти в комнату:

- комната может быть заполнена;
- комната может быть уже в статусе `playing`;
- комната может быть закрыта или удалена администратором.

Если старые ссылки на комнату возвращают `404`:

- администратор удалил комнату;
- вместе с комнатой удаляются связанные игра, ходы и чат.
